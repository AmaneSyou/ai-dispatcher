三分钟上手

AI 调度器帮你把编程任务分给三个 AI：DSH（DeepSeek，便宜，做简单重复的活）、Claude（复杂代码、调试、复核）、Codex（架构、疑难问题、拆分大任务）。它们各自在独立的副本里干活，做完自动检查，最后由你决定要不要放进项目。

  1. 环境检查：打开“环境检查”页，点“开始检查”。全部打勾再继续；没打勾的那一行会写怎么解决。
  2. 登记项目：到“设置 → 项目”，填项目名、仓库路径（必须是 git 仓库）和验收命令。第一次可以直接点“创建演示项目”。
  3. 新建任务：在“新建任务”页选项目，写标题和说明，“交给谁”选自动，点“加入队列”。
  4. 等它做完：任务会依次经过 排队 → 运行 → 验收 → 复核，完成后右下角弹通知，任务出现在“待你验收”。
  5. 验收：点开任务，看改了什么、AI 的汇报和复核意见。满意点接受并合并到项目，不满意点驳回并写原因。

关掉面板窗口不会停止调度器，它在后台继续干活。双击右下角托盘图标可以重新打开面板；右键托盘图标“彻底退出调度器”才会停止。

卡片第二行的意思：项目 · 当前 AI · 第 几/最多 轮 · 子代理 · 属于哪个大任务 · 自动合并。

一次复杂任务的完整流程

以“给暗黑地牢 1 做一个新增职业的大型 mod”为例，其他项目（网站、工具、游戏）流程一样。

① 准备（只做一次）

  • 建一个项目文件夹并初始化 git（例如 D:\mods\dd-plague）。
  • 把 AI 需要参考的东西放进项目里，例如原版游戏的职业文件放进 reference/。AI 在沙盒里读不到项目以外的文件（包括游戏安装目录）。
  • 写一页设计说明（例如 docs/设计.md）：要做什么、做到什么程度。
  • 先准备“自动验收”：派第一个任务让 AI 写一个检查脚本（格式对不对、ID 有没有重复、文本有没有漏）。以后每个任务都靠它自动把关，不用你每次都进游戏看。
  • 在“设置 → 项目”登记：验收命令填检查脚本；受保护文件填 reference/** 和检查脚本本身（防止 AI 改检查来蒙混过关）。

② 立项：发一个大任务

  • 新建任务，写清楚目标（可以直接说“按 docs/设计.md 实现”），勾选先拆分成小任务，由 Codex 拆分。
  • 几分钟后出现在“待你验收”：一份小任务清单，写着每项做什么、改哪些文件、要等哪几项。
  • 你可以直接改、删、加，满意后点批准并开始；不满意就写意见让 AI 重新拆分。

③ AI 干活（你可以去做别的）

  • “自动”分配：先判断难度，简单的给 DSH，难的给 Claude / Codex。
  • 没有先后关系的小任务同时进行；有先后关系的，等前一项合并进项目后才开始，这样它能拿到前一项的代码。
  • 每项做完自动跑验收命令；没过就带着错误信息重试，还不行就升级给更强的 AI。
  • DSH 做的，再让 Claude 复核一遍；复核发现问题会交回去改。
  • 每项进入“待你验收”时弹通知。

④ 验收

  • 点开任务看三样：改动（“最近一次验收结果”里列出改了哪些文件）、复核意见、AI 的汇报。
  • 满意：接受并合并到项目。会先在临时副本里合并并重新检查，有冲突或没通过就不动你的项目。
  • 不满意：驳回并写具体原因（“伤害太高，降到 4～7”），AI 会按意见改。
  • 拆分时勾了“自动合并”的，验收通过后会自己合并，你只需要最后整体看。

⑤ 实际使用 / 试玩

  • 合并后，项目文件夹里就是最新的成果。mod 之类需要放到别处才能用的，把它复制到游戏的 mods 目录，进游戏打开。
  • 如果调度器里的项目是副本（例如从备份建的），用任务详情里的导出补丁或推送到你的仓库，把改动带回你真正的仓库。

⑥ 发现问题 → 再派任务（循环）

  • 用的时候发现的问题，每条都写成一个新任务：写清楚现象和期望（“营地技能‘消毒’的文本显示成乱码，应该显示中文”）。
  • 小问题交给“自动”，几分钟修好；大改动（“重新平衡整个职业”）再发一个大任务让 Codex 拆分。
  • 修好 → 验收 → 合并 → 再试，直到满意。

你主要花时间在三件事上：写清楚想要什么、看结果、实际用。中间的分配、实现、检查、复核、重试都由调度器负责。

怎么写好任务说明

写得越具体，便宜的 AI 越容易一次做对，越省钱。

  • 要做什么：“在 src/text.js 实现 slugify”比“做个转换函数”好。
  • 改哪里：知道的话写上文件名；在“允许修改的文件”里限定范围（例如 src/**）。
  • 怎样算完成：“让 test/text.test.js 全部通过”“打开设置页时显示新开关”。
  • 不许碰什么：测试文件通常放进“禁止修改”，防止 AI 改测试来蒙混过关。
  • 举例子：输入什么、应该输出什么。例子能大幅减少误解。
  • 一个任务一件事。几件不相干的事，分开发，或者用“先拆分成小任务”。

三个 AI 怎么分工

AI适合花费
DSH（DeepSeek）说明清楚、改动小、重复性的活按 token 付费，很便宜；设置里有每日预算
Claude复杂代码、调试、复核用你的 Claude 订阅额度
Codex架构设计、跨很多文件、疑难问题、拆分大任务用你的 ChatGPT 订阅额度
  • 自动：先让一个 AI（默认 Codex，“设置 → 自动分配”里可以改成 Claude）快速看一下代码、判断难度，再交给最合适又最省钱的那个。
  • 升级：一个 AI 用完轮数还没通过，就按“设置 → 升级顺序”交给下一个（默认 DSH → Claude → Codex → 你）。接手的 AI 会看到上一个 AI 的汇报。
  • 互相接管：Claude 或 Codex 一方额度不够时，排队的任务自动转给另一方。
  • 子代理：一个 AI 再分出几个“小帮手”同时干活，适合能拆成几块互不相干的工作。很费额度，默认不开。

验收、合并、带回你的仓库

按钮做什么
接受并合并到项目先在临时副本里合并并重跑验收，都通过才放进项目的基线分支。你项目里有未提交的改动时会拒绝，不覆盖你的工作。
只接受（我自己合并）只标记接受，分支保留，之后可以再点“合并到项目”或自己用 git 合并。
驳回写上原因，重试时 AI 按意见改。
交给它重做 / 换它接手换一个 AI，在当前这一版基础上继续。
从头重来丢掉这一版，从原始代码重新做（你的意见仍会带上）。
撤销合并新增一个“反向提交”抵消那次合并，历史不会丢。
让 AI 在最新代码上重做合并时冲突或检查没过才出现：带着原因，从项目最新代码重新做。
导出补丁把任务的全部改动压成一个补丁文件，在你自己的仓库里运行 git am 补丁文件 应用。
推送到你的仓库项目设了“同步目标”才有：在你仓库的最新代码上应用改动，推到新分支 dispatcher/task-编号。不碰你已有的分支和工作目录，冲突就不推。

额度和花费

  • 额度保护：Claude / Codex 的订阅额度剩余降到“设置 → 额度保护”里的比例（默认 15%）就不再自动派活，剩下的留给你自己聊天用。
  • 付费额度：默认关闭。开启后，订阅额度用到保留线还会继续，用付费额度干活；每天有次数和金额上限。
  • DSH 预算：“设置 → DSH → 每日 token 预算”，用完当天就不再派给 DSH。
  • “额度”页能看到各家剩余多少；判断难度、复核也会用掉一点额度，可以在设置里关掉复核。

常见问题

没找到相关问题。可以换个词，或者看看上面的流程说明。

任务一直在“排队中”不动？

卡片上通常写着原因：

  • “等待 Claude / Codex 额度恢复”：额度用完或到了保护线，到点会自动继续。急的话可以点开任务换给别的 AI。
  • “等待 #X 合并进项目后开始”：它依赖的前一个子任务还没合并。去把 #X 合并（或开自动合并）。
  • “当前不可用”：那家 AI 没启用或没登录，去“环境检查”看看。
  • DSH 今日预算用完：到“设置”里调高预算，或者等明天。
“需要你处理”是什么意思，怎么办？

AI 自己解决不了了，需要你看一眼。点开任务，最上面写着原因：

  • 轮数用完仍未通过验收：看“最近一次验收结果”里哪一项打叉，补充说明后点“在原基础上重试”，或换个更强的 AI 接手。
  • 审计终止：AI 试图做不允许的事（改工作区外的文件、读密钥、执行 git push 等），已被强制停下。看事件记录，确认没问题后重试。
  • 准备命令失败：通常是装依赖时网络不通或项目本身有问题。看事件里的输出，处理后点重试；这不算 AI 的轮数。
  • 调度器重启时被中断：点重试即可。
验收没通过，怎么看是哪里出了问题？

任务详情里“最近一次验收结果”逐项列出：✔ 通过、✘ 没通过，后面跟着命令输出。常见的：

  • 没有任何改动：AI 没真正改文件，通常说明任务说明不清楚。
  • 受保护文件 / 只读文件被改了：AI 动了不许动的文件，直接判不通过。
  • 不在允许范围：改了“允许修改的文件”以外的地方。
  • 验收命令失败：看下面的输出，就是你项目自己的测试或检查报的错。
驳回后“重试”和“从头重来”有什么区别？

“重试”在上一版基础上按你的意见改（同一个 AI 还能接着原来的对话）；“从头重来”丢掉这一版，从原始代码重新做，但你的意见仍然会交给 AI。改得基本对、只差一点用“重试”；方向完全错了用“从头重来”。

合并会直接改我电脑上的项目文件吗？

会，合并就是把改动放进项目的基线分支（通常是 main）。如果你当前检出的正是这个分支，文件夹里的文件会变成新版本。但它很小心：先在临时副本里合并并重新检查，没问题才更新；你项目里有未提交的改动时会拒绝合并，不会覆盖；合并后还可以“撤销合并”。

合并时提示“冲突”怎么办？

说明两个任务改了同一处，或者项目在这期间又变了。项目不会被改动。点“让 AI 在最新代码上重做”，它会基于最新的代码重新完成这个任务；也可以导出补丁自己处理。

调度器里的项目是副本，怎么把改动带回我真正的仓库？

任务详情里点“导出补丁”，得到一个 .patch 文件，在你的仓库里运行 git am 补丁文件。或者在“设置 → 项目”里填“同步目标”（你仓库的路径或 GitHub 地址），之后可以点“推送到你的仓库”，它会推到一个新分支 dispatcher/task-编号，你检查后自己合并。大任务可以“导出全部子任务补丁”，按文件名顺序依次应用。

为什么有些文件 AI 改不了（受保护）？

两类文件默认受保护：一是凭据和锁文件（.env、*.lock、CI 配置）；二是验收时会被执行的构建配置（build.rs、.cargo、.npmrc 等）——AI 改了它们，验收时就可能在沙盒外执行任意程序。项目设置里还可以额外加（例如 package.json、vite.config.*）。确实需要改时，临时从项目的受保护列表里去掉，或者你自己改。

“准备命令”是什么？什么时候要填？

每个任务的副本都是新拉出来的干净代码，没有 node_modules 这类没进 git 的东西。准备命令在 AI 开始前先跑一次，通常用来装依赖，例如 装依赖 | pnpm install --frozen-lockfile --prefer-offline。项目不需要装依赖就留空。它在沙盒外运行，可以联网；失败不算 AI 的轮数。

项目要用 pnpm / Rust / Python，电脑上没装？

运行程序目录里的 安装工具.ps1（右键 → 使用 PowerShell 运行），它会把选中的工具装进程序目录的 tools 文件夹，不改系统设置，只从官方地址下载并核对校验值。装好后在“环境检查”里能看到。删掉 tools 文件夹就是卸载。

没有收到通知？
  • 右键托盘图标 →“发一条测试通知”，看能不能弹出来。
  • Windows 的“专注助手 / 勿扰”开着时，通知不弹出，只进通知中心（任务栏最右边）。
  • “设置 → 通知”里检查对应的开关是否勾上。
  • 托盘图标不在了说明调度器没在运行，双击桌面“AI 调度器”重新打开。
关掉面板窗口，任务还会继续吗？怎么彻底退出？

会继续，调度器在后台运行。双击托盘图标重新打开面板。要彻底停止：右键托盘图标 →“彻底退出调度器”，或面板右上角“退出调度器”。正在运行的任务会被停下，下次启动时标为“需要你处理”，点重试即可。

会不会占很多磁盘？

任务结束后会自动整理：日志压缩存档，删掉 DSH 的会话目录和用过的副本。主要占空间的是工具和共用缓存：Rust 工具链约 800 MB，Rust 编译缓存（工作目录\cargo-target）几个 GB，依赖缓存几百 MB——它们是所有任务共用的，不会随任务数增长。cargo-target 可以随时删，只是下次编译慢一点。

AI 会不会乱改我电脑上的东西？

每个 AI 都在各自的沙盒里，只能写任务副本；调度器还实时审计每一步，读密钥、写副本以外的地方、git push、申请提权等都会立刻终止它。需要注意的是验收命令在沙盒外、以你的身份运行（它要执行 AI 改过的代码来检查），所以只把你信得过的项目交给它，难的任务尽量在你在场时跑，并把构建配置加进受保护文件。

DeepSeek key 放在哪？泄露了怎么办？

单独保存成文本文件 工作目录\secrets\deepseek.key，文件里只放 key 本身。调度器不会在面板或日志里显示它，AI 也读不到这个目录。不要截图或发给别人。万一泄露，立刻到 DeepSeek 开放平台删除这个 key 并新建一个，替换文件内容即可。

大任务的拆分方案不满意？

在“待你验收”里打开它，可以直接改每一项的标题、说明、允许修改的文件、交给谁、要等哪几项，也可以删掉或添加；改完点“批准并开始”。不想自己改就点“让 AI 重新拆分”，写上意见（例如“拆成 3 项，第 3 项依赖前两项”）。

复核是什么？可以关掉吗？

验收通过后，让另一个 AI 再看一遍改动，只提会导致出错或漏需求的重要问题；发现问题会交回原来的 AI 修改（默认最多返工 1 次）。默认只复核 DSH 做的。复核会用掉一点 Claude / Codex 额度，“设置 → 复核”里可以关掉或改成全部复核。复核的 AI 都没额度时不会等，直接交给你并写明“没有复核”。

怎么换背景图、调透明度？

“设置”最上面的“外观”：选择图片做背景，拖动滑块调面板不透明度、毛玻璃模糊和背景变暗，会立即预览，满意后点“保存外观”。

安全须知

  • 只登记你信得过的项目：验收命令会在沙盒外以你的身份执行 AI 改过的代码。
  • 把“验收时会被执行的配置”（package.json、构建脚本、打包配置）加进受保护文件。
  • 测试文件放进“禁止修改”，防止 AI 改测试蒙混过关。
  • 合并前看一眼改动，尤其是复核提出问题、或标着“可疑改动”的任务。
  • key 只放在 secrets 文件夹，不要写进项目代码或任务说明里。
  • 面板只能在本机打开，每次启动都换一个新口令，别的网页没法冒充你操作。
